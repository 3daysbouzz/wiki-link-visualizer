## 決めた方式

**rev4 の `cameraFit` を `d`(今の中心と、関連スコアの上位の子=確定枠 10件が入る距離)にした。**

候補ごとのまとめ(12経路 × 復元・歩く × pc・phone = 48 組):

| 候補 | 完了条件を満たさない組 | M5 周回の平均(48組の平均) | M6 周回の平均(48組の平均) | カメラ距離(平均) | 前の中心が画面内 | 移動ごとの比の最大 |
|---|---|---|---|---|---|---|
| a | 0 | 8.9 | 69.8 | 533 | 46/48 | 1.46 |
| b | 1(none-air・復元・phone の M6 が rev3 より悪い) | 10.0 | 85.1 | 565 | 46/48 | 2.17 |
| c | 0 | 8.9 | 69.8 | 533 | 46/48 | 1.46 |
| **d** | **0** | **8.2** | **62.0** | **512** | **46/48** | **1.43** |

選んだ理由(指示書の優先順):

1. 完了条件: a・c・d がすべて満たした(b は none の組で前の中心まで広げるため、phone の M6 が rev3 より悪くなった)
2. 共通ワードの読みやすさ: a〜d のすべてで、保証した1件が周回の最悪でも読める
3. phone の混み具合: d がいちばん小さい
4. 前の中心が画面に入る割合: a・c・d で同じ(入らない2組は、どれも none-choco の「歩く」。前後の中心が画面上で約 490px 離れる)
5. 移動ごとの距離の変化: d がいちばん小さい

c は、前の中心がほとんど「a の範囲の 1.2 倍以内」に入らず(入っても範囲が変わらず)、a と同じ数字になった。
d は遠くに飛んだ子に引っ張られない。work の復元で a 580 → d 498、none-air の復元で a 688 → d 553 など、子が1件でも遠い経路で差が出る。

## 事実として言えること

- rev4(d)の最初のカメラ距離は、URL の復元で 498〜651(07 の決め方では 914〜1225)、検索して歩く場合で 456〜477(07 では 727〜756)
- science の URL 復元は、pc の M5 が rev3 の 9 → 4、M6 が 66 → 16、phone の M5 が 41 → 19、M6 が 349 → 96 になった
- phone の M5(中心から 60px 以内の一次ノード)は、rev3 の 20〜41 に対して rev4 は 7〜28
- 前後の中心の画面上の距離は広がった(例: work の復元・pc 17.8 → 32.8px、phone 8.4 → 15.4px)
- M3(上位10件の子のラベルが読める件数)は多くの組で増えた(例: work の復元・pc 周回の平均 2.4 → 4.4)
- **M8(回転中の点滅)は、phone で増えた**(例: work の復元・phone 16 → 53、science の歩く・phone 31 → 50)。
  カメラが寄ったぶん、回したときに画面上で動く量が大きく、ラベルの入れ替わりが増えたと思われる
- Wikipedia から取った展開結果(既定の4経路)でも、完了条件はすべて満たした(08 の作業日に測定)

## 測り方の限界

- 保存した展開結果での測定は、閲覧数を使わない(一次ノードはすべて最小の大きさ)。実際の表示とは球の大きさが少し違う
- 「歩く」場面は、1件進むごとに配置が落ち着いてから次へ進む。実際には落ち着く前にクリックすることもある
- none の組(none-choco)の「歩く」では、前の中心が画面の外に出る(前後の中心が画面上で約 490px 離れる)。合意済みの限界

# タスク: Wikimedia API への同時リクエスト数を全体で3以下にする

作成日: 2026-09-29 / 対象: `wiki-link-visualizer-public`(基準コミット `e04aac2`)

## 目的

Wikimedia の推奨(Wikimedia APIs/Rate limits: 同時リクエスト 3 以下)を守る。
現状は閲覧数(R1)だけ最大8本並列で、Action API と REST summary(R2)には同時実行の制御がなく、
展開(4本)とサイドバー(3本)が重なると Wikipedia への同時接続が10本を超えうる。

出典(公開前に全文で再確認すること): https://www.mediawiki.org/wiki/Wikimedia_APIs/Rate_limits

## スコープ

含む: Wikipedia / Wikimedia への全通信を1つの行列に通し、同時実行数を上限までに抑える。
含まない: 429 の待機・`Retry-After`(別タスク)、`Api-User-Agent`、リクエスト件数そのものの削減、`path` の件数上限、英語版対応(見送り決定)。

## 仕様

1. **全通信を1つの行列に通す**
   - `fetch` を直接呼ぶのは `fetchWithTimeout`(wikipedia.js:94)だけ。ここを行列経由にする。
   - `summary.js`(R2)も同じ関数を通す形にそろえる。
   - `scripts/fetch-long-walks.mjs` は `wikipedia.js` 経由なので同じ行列の対象になる(問題があれば報告)。
2. **同時実行数の上限は定数にする**
   - 例: `MAX_CONCURRENT_REQUESTS = 3`(`src/constants.js`)。
   - 既存の `VIEWS_CONCURRENCY=8` は廃止するか、全体上限以下にする。二重制御にしない。
   - `?debug=1` のときだけ URL で上書きできるようにする(計測用。公開版の挙動は変えない)。
3. **タイムアウトは実行開始時から数える**
   - 15秒(`FETCH_TIMEOUT_MS`)は、行列で待っている間は進めない。
   - `AbortController` は送信する直前に作る。
4. **優先度は3段階**
   - 高: 利用者の操作による展開(A1〜A5)
   - 中: サイドバー(R2, A6, A7)
   - 低: 閲覧数の先読み
   - 閲覧数の表示分(現状の high)は、先読み(low)より先に処理する現在の挙動を維持する。
   - 同じ優先度の中は先に入れた順。
5. **待機中のリクエストは取り消せる**
   - まだ送信していない待機分だけ破棄できる。送信済みは中断しない(現状どおり)。
   - ホバー(300ms)で別ノードへ移ったとき、検索候補(A8)で古い入力になったときに破棄する。
   - 破棄された呼び出しは、エラーではなく「取得しなかった」として扱う(キャッシュに失敗を保存しない)。

## 変更しないこと

- キャッシュの仕組み、リクエストの内容・件数、エラーメッセージ。
- グラフの表示・力学・URL の仕様。

## 手順

1. 作業用ブランチを切る(例: `feature/concurrency-limit`)。`main` には触れない。
2. 変更前の計測を記録する(基準コミット `e04aac2`)。`?debug=1` の `window.__viz.measure()` で、
   代表的な操作の「表示までの時間」を数回ずつ測る。結果は `docs/` に保存する。
3. 実装する。
4. テストを追加する。偽の `fetch` で同時実行数を数え、常に上限以下であること、優先度順に処理されること、
   待機中の破棄が効くこと、タイムアウトが実行開始から数えられることを確認する。既存テストも通す。
5. 変更後に同じ計測をして、手順2と比べる。
6. ブラウザの Network タブで、展開直後とホバー連打のときに同時に pending になる接続が上限以下であることを目視する。

## 完了条件

- 全通信の同時実行数が、テストとブラウザで確認して上限(3)以下。
- 既存テストがすべて通る。
- 変更前後の計測結果が `docs/` にあり、体感のラグが許容できるかを人が判断できる。

## 注意

- 閲覧数(最大25件)が3本ずつになるため、表示が遅くなる可能性がある。遅さの許容は計測結果を見て人が判断する。
  遅すぎる場合は、上限の値を変える前に、閲覧数の件数削減(別タスク)を先に検討する。
- 上限を3より大きくする場合は、Wikimedia の推奨から外れることを承知の上で、理由を記録する。

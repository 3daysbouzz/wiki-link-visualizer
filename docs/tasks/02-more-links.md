# タスク02: 関連リンクの追加表示(中心タップ / + MORE ボタン)

CLAUDE.md と SPEC.md(3.3〜3.5・5章・6章・7章・12章)を読んでから着手すること。
前提: 01(関連スコア方式)

## 背景

1記事から出すリンクは neighborLimit 件(40件)に絞っている。
散歩中に「この記事の周りをもう少し見たい」ときに、その場で増やせるようにする。
増やす分は、まだ出ていない候補のうち関連スコアの高いものを優先する。
通信待ちで重くならないよう、次に出す分は裏で準備しておき、いつでも即座に出せるようにする。

当初は「中心ノードを振ると増える」ジェスチャーを検討したが、スマホで振る操作は難しいため、
入口はタップとボタンにし、「振る」手触りは演出(5章)で残す。

## 仕様

### 1. 操作(入口は2つ。どちらも同じ処理を呼ぶ)

- **中心ノードのタップ/クリック**
  - 現在地ノードをクリックしたときに追加を実行する
  - 現状、現在地ノードのクリックは `jumpTo(現在地)` になり実質何もしていないので、この分岐を置き換える
  - 訪問済み(中空)ノードのクリック=そこまで戻る、の動作は変えない
  - 現在地ノードにカーソルが乗ったときに cursor が pointer になっていることを確認する
- **サイドバーの「+ MORE」ボタン**
  - 「隣接記事 (N)」の見出しの横に置く。表記の例: `+ MORE 8`、残数 `REST 32`
  - サイドバーがホバー先の記事を表示している間は隠す(どの記事に足すのか紛らわしくなるため)
  - 追加できる残りが 0 件、または取得中のときは disabled にする
  - `<button>` と `aria-label` を付ける(デザイン規則: 角丸・絵文字なし)
- 初めてグラフを表示したときだけ、左上のステータス行に「中心をクリックで関連記事を追加」を数秒出す

### 2. 追加する候補の選び方

- 対象は、その記事の候補プール(POOL_SIZE 件、スコア順)のうち、まだ表示していないもの
- **抽選はせず、スコアの高い順に** `moreBatch` 件ずつ出す
- 1記事あたりの追加の上限は `moreMax` 件。上限に達したら残数 0 として扱う
- `moreBatch=8`、`moreMax=40` を VizConfig に入れ、URL と leva(ranking フォルダ)で変えられるようにする
- 候補プールは linkCache にあるので、wikipedia.js に追加分を返す関数を用意する
  (例: `getMoreLinks(title, shownTitles, count, weights)`)。
  追加で Wikipedia に問い合わせることはしない

### 3. 裏での準備(先読み)

- 追加分の候補そのものは取得済み。裏で準備するのは、次に出す moreBatch 件の閲覧数(球の大きさ)
- 現在地のグラフが表示され、表示分の閲覧数の取得が終わったら、次の moreBatch 件の閲覧数を先読みする。
  追加を実行したら、さらに次の分を先読みする
- 先読みは表示中の取得より優先度を下げる(表示分が終わってから始める)。同時実行数は `VIEWS_CONCURRENCY` を超えない
- 先読みが間に合っていなくても追加は即座に行う。大きさは届いた時点で育てる(既存の閲覧数と同じ扱い)

### 4. 状態の保持

- 追加した結果は `expansions` に記憶する(その記事の links に追記)。
  グラフは今まで通り trail から毎回組み立て直す(CLAUDE.md の約束を崩さない)
- 戻る/進むで、追加したノードが消えたり別の顔ぶれになったりしないこと
- URL には追加分を保存しない(経路の復元時は追加前の状態になる)。この制約を SPEC に明記する

### 5. 演出(「振る」の手触りを残す)

- 追加の瞬間、現在地ノードを短く震わせる(例: 250ms・画面上 ±5px 程度の減衰振動)。
  時間と振幅は constants.js に置く
- 新しいノードは現在地ノードの位置(seed 由来の微小なずれ付き)から出現させ、
  シミュレーションを再加熱(alpha を戻す)して外へ広がらせる
- 追加したノードのラベルは数秒間、ラベル間引きの優先度を上げる(何が増えたか読めるように)
- 上限に達しているときに中心をクリックしたら、震えを小さくし、ステータス行に「これ以上の関連記事はありません」を出す

## テスト(tests/)

- `getMoreLinks` が表示済みを除き、スコア順に count 件返す
- 残りが count 件未満ならあるだけ返し、0 件なら空配列
- 同じ入力なら同じ結果(決定論)
- 上限 moreMax を超えない

## 完了条件

- 中心クリックと + MORE の両方で8件ずつ増え、上限40件で止まる
- 追加した直後に、別記事へ進んでから戻っても、追加分がそのまま残っている
- 追加時に通信待ちが発生しない(ステータスが取得中の表示にならない)
- スマホ横画面で、中心タップによる追加ができる(横画面対応が実装済みなら、ドロワーを閉じた状態で確認する)
- `npm test` が通る
- SPEC 5章・6章・7章・12.2、README の操作説明を更新する

# タスク 10: 輪を閉じたときの演出(イースターエッグ)

CLAUDE.md と SPEC.md(4章・5章・6.1・6.7・6.10・12章)を読んでから着手すること。
前提: 09 が完了し、利用者の実機確認が済んでいること

## 背景と目的

散歩の経路が輪になって閉じる(A → B → C → A と進み、今の中心から A へのリンクをたどって戻ってくる)のは、wiki のリンク構造そのものが起こす出来事である。
このツールの面白さの本質は wiki 自体にあるので、これを**説明しない演出(イースターエッグ)**として見せる。

- 画面にボタンや説明は足さない。気づいた人だけが驚く仕掛けにする
- 3件の小さな輪はよく起きるので、そこで規則に気づいてもらい、長い輪を狙いたくなるようにする
- 輪の長さで演出を変える。長い輪ほど色が先へ進み、6件以上ではカメラワークを見せる

利用者との合意事項(2026-09-26):

- 数えるのは、中心が3件以上の輪だけ。A → B → A は多角形にならないので、何も起こさない
- 条件は、今の中心から伸びる子をクリックして(ノードでもサイドバーの隣接記事でもよい)、前に通った記事に戻り、輪が閉じること。
  パンくず・Backspace での戻りは数えない
- 演出の色: 3件 = 黄、4件 = 黄緑、5件 = 緑。長いほど一方向に色が進む。9件で青に近い色、までの並びにする
- カメラワークは6件以上だけ。境目は定数で、初期値は6(身内の試用を見て調整する)。5件以下は今のカメラのまま光らせるだけ。
  ただし、輪全体が画面に収まる程度に、小さくカメラを引いてよい(スマホで前の中心が画面の外に出ることがあるため)
- 輪を閉じられる記事(今の中心の子のうち、2つ以上前に通った記事)には、控えめな合図を出す(下の仕様3)
- 色は、この演出の中だけで使う。常設の表示には使わない(CLAUDE.md の表現のルールの、明示的な例外)

## 用語

- **輪**: 経路 `shown` の i 番目の記事から今の中心(末尾)までの並びに、今の中心から i 番目の記事へのリンク(子の線)を加えた閉じた経路
- **輪の長さ**: 輪に含まれる中心の数(末尾の位置 − i + 1)
- **輪の候補**: 今の中心の子(`expansions`)のうち、経路の中で2つ以上前にある記事(クリックすれば長さ3以上の輪になる記事)

## 段階の分け方

作業を2段階に分け、段階の間で一度止まる。

- **10a**: 輪の判定、輪の候補の合図、3〜5件の演出、デバッグの入口
- **10b**: 6件以上のカメラワーク(10a の演出を利用者が見てから着手する)

## 仕様

### 0. 着手前の報告(ここで一度止まる)

1. 訪問済みのノードをクリックしたときの今の処理(戻る処理)の流れと、演出を「先に再生してから戻る」順番に差し込める場所
2. 線と球の色を、演出の間だけ変える方法(線は頂点の色、球は `SpriteMaterial` の色で足りるか)
3. 07 の「注目状態」(ホバーと到着時の強調)との関係
4. 指示書と現在のコードとのずれ

### 1. 輪の判定(10a)

- 純粋関数 `detectLoop(shown, expansions, clickedId)`(`src/utils/relation.js`)が、輪の長さ(輪でなければ 0)を返す
  - `clickedId` が経路の中にあり、今の中心の子であり、輪の長さが3以上のときだけ輪とする
- ノードのクリックとサイドバーの隣接記事のクリックで判定する。パンくず・Backspace・検索・URL からの復元では判定しない
- `?debug=1` のときは、輪を閉じるたびに Console に輪の長さと顔ぶれを出す(試用で、実際にどのくらいの長さの輪ができているかを知るため)

### 2. 3〜5件の演出(10a)

**順番**

1. 輪を判定したら、今の戻る処理の前に演出を再生する。輪の線(経路の線と、今の中心 → 戻り先の子の線)は、戻る処理で消えるので、先に見せる必要がある
2. 演出の間はクリックを受け付けない(今のカメラの移動中と同じ扱い)。ドラッグ・ホイール・キー操作があれば、演出を早送りで終える
3. 演出が終わったら、今までどおりの戻る処理を行う(経路が戻り先で切られる)

**見せ方**

- 輪の線と、輪を作っている中心の球を、輪の長さに応じた色にする
- 光が戻り先 → … → 今の中心 → 戻り先の順に輪を一周するように、線の明るさを順に上げる(色の違いに頼らず「周回した」ことが伝わるようにするため)
- 一周したら、色と明るさを通常に戻しながら消える。全体の長さの目安は2秒前後
- 輪全体が画面に収まっていなければ、収まる程度にカメラを小さく引く(向きは変えない)
- 輪の線は太線を使わず、今の線の色で描く

**色**(定数。`EGG_COLORS` など。長さの順に一方向に進める)

| 輪の長さ | 色 |
|---|---|
| 3 | 黄 |
| 4 | 黄緑 |
| 5 | 緑 |
| 6〜9(10b のカメラワークと一緒に使う) | 緑から青に近い色へ一方向に進める |

**安全**

- 1秒間に3回を超えて点滅させない
- `prefers-reduced-motion: reduce` のときは、光が一周する動きを行わず、色を付けて消えるだけにする

**到着時の強調との関係**

- 輪を閉じた後の戻る処理では、到着時の共通ワード強調は出ない(強調は進んだときだけ出る決まりなので)。そのことを確かめる

### 3. 輪の候補の合図(10a)

- 輪の候補の球の**明るさだけ**を、ゆっくり脈打たせる。大きさ・リングは変えない
- 周期は、今の中心の呼吸(3.2秒)と見分けがつく値にする
- 明るさは半透明にせず、色を暗くする方法で揺らす(重なったときに奥が透けないように)
- 色は使わない(白のまま)。色は輪が閉じた瞬間のご褒美として取っておく
- 到着時の強調をしている間は合図を止め、強調が終わってから始める
- 候補が複数あれば、すべてに合図を出す(多すぎると感じたら、いちばん長い輪になる1件だけに絞ることを後で検討する)
- 純粋関数 `loopCandidates(shown, expansions)` で求める
- CLAUDE.md の割り当ての一覧を「脈動 = 輪を閉じられる記事の合図」に書き換える

### 4. 設定とデバッグ(10a)

- VizConfig に `easterEgg`(見た目だけの項目)を足す。rev5 は on、rev4 も on、current・rev2・rev3 は off
- `?debug=1` のとき `window.__viz.egg(n)` で、今の画面に長さ n の輪の演出を試せるようにする(輪がなくても、経路と周りのノードを使って見た目を確かめられればよい)。3〜9 のすべてを試せること
- 定数: `EGG_CINEMATIC_MIN`(6)、色、演出の長さ、合図の周期。決めた値と理由をコメントに残す

### 5. 6件以上のカメラワーク(10b。10a の後で着手する)

- 輪全体が収まる位置までカメラを引き、輪の重心の周りを一周する。光は輪を何周か走る
- 画面の隅に、端末風の白い文字を一行出してよい(例: `LOOP CLOSED // 6 NODES`)。書体は JetBrains Mono、色は白。絵文字は使わない
- 全体の長さの目安は5秒前後。ドラッグ・ホイール・キー操作で早送りして終える
- 終わったら、今までどおりの戻る処理(戻り先へのカメラの移動を含む)を行う
- `prefers-reduced-motion: reduce` のときはカメラワークを行わず、3〜5件と同じ演出にする

## テスト(tests/)

- `detectLoop`: 長さ3以上の輪を検出する。A → B → A(長さ2)は 0。今の中心の子でない記事は 0。経路にない記事は 0。経路の途中から始まる輪(A → B → C → D と進み、D から B へ戻る = 長さ3)を検出する
- `loopCandidates`: 2つ以上前に通った記事だけを返す。1つ前の中心は含めない
- 色の並びが、長さの順に一方向に進む
- `easterEgg` の既定値が、プリセットごとに上のとおりになっている
- current・rev2・rev3 の配置とカメラ距離が、09 完了時と一致する
- 既存のテストがすべて通る

### 0章の報告(前のセッションで調べた結果)

1. **戻る処理の流れと差し込む場所**
   - 訪問済みのノードをクリック → `handleNodeClick`(src/App.jsx)が `trailNow.includes(node.id)` を見て `jumpTo` を呼ぶ → `jumpTo` が
     `commitTrail(current.slice(0, index + 1))` と `travelTo(title)` を行う。サイドバーの隣接記事も `handleSidebarSelect` 経由で `handleNodeClick` を通る。
     パンくず・Backspace は `jumpTo` を直接呼ぶ(`handleNodeClick` を通らない)
   - **差し込む場所**: `handleNodeClick` の `jumpTo(node.id)` の直前で `detectLoop` を呼び、輪なら演出を再生 → 終わってから `jumpTo`。
     これでパンくず・Backspace では自然に何も起きない
   - 演出中のクリック止めは、専用の ref を立てる(今の `travelingRef` は `TRAVEL_MS` で自動的に外れるので流用しない)。
     `jumpTo` は `travelingRef` を見て弾くので、演出の後に呼ぶ前に必ず外しておくこと
   - **輪の線は今のグラフにすでにある**: `buildGraph` は今の中心の子の線を、行き先が経路の記事(2つ以上前)でも `type: 'child'` で引く
     (1つ前の中心への線だけは trail の線と同じ2点なので省かれるが、それは長さ2 = 輪にしない場合)
2. **色の変え方**
   - 線: 実線・破線とも `vertexColors: true`。今は `updatePositions`(src/components/Graph3D.jsx)で `link.bright` を RGB 全部に同じ値で書いている。
     線ごとに色を持たせて「色 × 明るさ」を書けば足りる
   - 球: 白い円のテクスチャなので、`SpriteMaterial` の `color` を掛ければ色が付く(訪問済みの中空の輪も同じ)
   - 輪の候補の合図も `material.color` を暗くする方法で揺らせる。今の減光は `material.opacity`(半透明)なので、その上に色の暗さを掛け合わせる形になる
3. **注目状態との関係**
   - ホバーと到着時の強調は `applyHighlight`(目標値)→ `updateVisuals`(毎フレーム補間)の同じ仕組み。打ち切りは pointerdown・wheel・keydown で `cancelArrival` を呼んでいる
   - 演出はこれに3つ目の状態として乗せ、いちばん優先する: 始めるときに到着時の強調を打ち切り、演出中はホバーを無視し、ドラッグ・ホイール・キーで早送りして終える
   - 戻る処理では `startsArrival` が false なので、輪を閉じた後に到着時の強調は出ない(テストで確かめる)
   - 輪の候補の合図は、到着時の強調の間は止める
4. **指示書とコードのずれと、その扱い**
   - `loopCandidates` は 09 で `src/debug/measure.js` に作った(M10 の計算)。**`src/utils/relation.js` に移し、表示と `measure()` が同じ関数を呼ぶようにする**(CLAUDE.md の決まり)
   - 「脈動」は、取得中のノード(`ctx.loadingId`)の**大きさ**の脈動ですでに使われている。輪の候補の合図は**明るさだけ**なので見分けはつく。
     CLAUDE.md の一覧は「大きさの脈動 = 取得中 / 明るさの脈動 = 輪を閉じられる記事の合図」と分けて書く
   - テストの「current・rev2・rev3 の配置とカメラ距離が 09 完了時と一致する」は、09 で作った `tests/rev5.test.js`
     (期待値 `tests/fixtures/camera-layout-at08.json`)がそのまま使える。09 で配置・カメラの計算は変えていないので 08 完了時 = 09 完了時。新しく作らない
   - ドキュメントの「00-workflow.md: 表に 10 を加える」は済んでいる(状態を更新するだけ)
   - リダイレクトで経路上の記事に並び替わる場合(未訪問の子をクリックしたら解決後の名前が経路の記事だった)は、経路が切られず末尾へ並び替わるだけなので、輪として扱わない

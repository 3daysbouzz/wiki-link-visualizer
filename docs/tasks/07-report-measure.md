## 事実として言えること

- **中心同士の距離は段階ではっきり分かれた。** 隣り合う段階の比は最悪値で 1.350・1.357・1.351(どれも 1.3 以上)
- **M9(共通ワードの読める件数)は rev4 で増えた。** 周回の最悪値で work pc 0 → 3、science pc 0 → 1、coffee pc 0 → 2、
  phone の work・science 0 → 1。平均も全経路で rev3 以上(例: work pc 1.9 → 3.6)
- **ただし上位の共通ワードの全部は読めない。** 読めなかった理由はすべて overlap(対象どうしの重なり)。
  共通ワードは前後の中心の間に集まり、初期視点のカメラ距離(約 900〜1200)ではラベル同士が重なる
- **science の rev4 は M3〜M6 が悪くなった。** none の組が離れて全体が広がり、初期視点のカメラ距離が 925 → 1225 に伸びた。
  そのため画面上でグラフが小さくなり、M5 は pc 9 → 18、M6 は phone の 32px 未満の組が 349 → 627 に増えた。
  ほかの経路の M3〜M6 は rev3 とほぼ同じ(差は数件)
- **M1・M2 は rev4 で rev2 に近い値に戻った**(子の距離を使わないため)
- M7 はすべて 418(変わらない)。M8 は経路によって増えたり減ったりで、一定の傾向はない

## 解釈・推測

- 到着時の強調は「どれが共通ワードか」を見せる効果はあるが、共通ワードが多い組(8件)では名前どうしが重なるため、
  「どの角度でも読める」には届いていない。カメラを寄せる・対象どうしの重なりを許す・件数を減らす、のいずれかが要る
- none の組を離すと、全体を収める初期視点ではグラフが小さくなり、今の中心の周りが混む(science で M5・M6 が悪化)。
  初期視点の距離を「全体」ではなく「今の中心の周り」で決めるなどの対応は、カメラの決め方の変更になるので別タスクで扱う

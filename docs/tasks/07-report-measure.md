## 事実として言えること

- **中心同士の距離は段階ではっきり分かれた。** 隣り合う段階の比は最悪値で 1.350・1.357・1.351(どれも 1.3 以上)
- **M9: rev4 は全経路・両画面で、保証した1件が周回の最悪値でも読める。** rev2・rev3 では同じ1件が最悪値 0 件
- M3(上位の子の読める件数)は rev4 と rev3 でほぼ同じ(差は 0〜2件で、向きは経路によって違う)
- M1・M2 は rev4 で rev2 に近い値に戻った(子の距離を使わないため)
- M7 はすべて 418(変わらない)。M8 は経路によって増えたり減ったりで、一定の傾向はない

## 既知の制限

- **science 経路の rev4 は、画面が混む(M5・M6 が悪化)。**
  none の組(流体力学 → マグネシウム)が 540 まで離れて全体が広がり、全体を収める初期視点のカメラ距離が 966 → 1231 に伸びる。
  そのため画面上でグラフが小さくなり、今の中心の周りが混む。

  | 項目(初期視点) | science pc rev3 → rev4 | science phone rev3 → rev4 |
  |---|---|---|
  | M5 中心から 60px 以内の一次ノード | 13 → 15(周回の平均 11.8 → 18.1) | 41 → 41(上限。一次ノードのほぼ全部) |
  | M6 32px 未満の組(中心を含む) | 83(5) → 133(6) | 403(21) → 662(27) |
  | M6 44px 未満の組(phone) | — | 762 → 1126 |

  原因は最初のカメラ距離の決め方(全体が収まる距離)なので、タスク08(最初のカメラ距離の決め方)で扱う。
  既定のプリセットは rev2 のままなので、公開版の利用者には影響しない。rev4 を既定にするかは 08 のあとで判断する

  **08 で対応した結果(2026-09-27)**: rev4 の最初のカメラ距離を「今の中心と確定枠の子が入る距離」(`cameraFit` d)にした。
  同じ実行(保存した展開結果)で、science の URL 復元は カメラ距離 1225 → 562、pc の M5 18 → 4(rev3 は 9)、
  M6 135 → 16(rev3 は 66)、phone の M5 41 → 19(rev3 は 41)、M6 627 → 96(rev3 は 349)。rev3 より混まなくなった。
  なお、検索して手で歩く場合は、もともと最初の記事だけで距離が決まり(約 730)、この悪化は起きていなかった
  (06・07 の `measure()` は URL 復元の場面しか測っていなかった)。詳細は `08-report-measure.md`
- **共通ワードの名前を保証できるのは1件まで。** 2件以上は、共通ワードが多い組で角度によって重なる。
  画面上の中心同士の間隔(many で pc 約19px・phone 約9px)が狭いことが原因で、08 で広がれば増やせる可能性がある
- **Wikipedia 側の検索結果が変わると、同じ経路・同じ種でも子の顔ぶれが変わる。**

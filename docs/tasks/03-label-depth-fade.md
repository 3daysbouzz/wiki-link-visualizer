# タスク03: 奥にあるラベルを深さに応じて透けさせる(回して手前に持ってくると読める)

CLAUDE.md と SPEC.md(1章・6.1・6.3・12章)を読んでから着手すること。
前提: 別途実装中の「力学パラメータの VizConfig 化」、および 02(関連リンクの追加表示)が完了していること

## 背景

今はラベルが手前も奥も同じ濃さで出るため、全体が一度に見えてしまい「探索している感」が薄い。
現在地より奥にあるラベルを深さに応じて薄くし、一定以上奥では見えなくする。
グラフを回して手前に持ってきたときに初めて名前が読める、という体験にする。
球と線は今まで通り見せる(「そこに何かある」ことは分かる状態を保つ)。
この処理は奥行きの手がかりにもなり、SPEC 1章の「3D特有の読みにくさを UI 側で補償する」にも沿う。

## 仕様

### 1. 深さの定義

- 深さ = カメラの視線方向に沿った距離。
  式: `depth(p) = dot(p − カメラ位置, カメラの前方向ベクトル)`
  位置は `displayPosition`(ドリフト込みの表示位置)を使う
- 基準は現在地ノード。`delta = depth(ノード) − depth(現在地)`(正の値ほど現在地より奥)

### 2. ラベルの不透明度

- `depthFade = 1`(delta ≤ fadeStart)
- `depthFade = 1 − (delta − fadeStart) / (fadeEnd − fadeStart)`(その間)
- `depthFade = 0`(delta ≥ fadeEnd)
- ラベルの最終的な不透明度 = 既存の不透明度(ホバー時の減光など) × depthFade
- depthFade は毎フレーム計算し、既存のホバー遷移と同じ方式で滑らかに補間する
  (ラベルの選び直しは 200ms 間隔なので、それに合わせるとカクつくため)
- 初期値の目安: fadeStart = 0、fadeEnd = springLength の2倍程度(ワールド座標)。
  実際に見て調整するので、最終値と決めた理由を constants.js のコメントに残す

### 3. 例外(常に depthFade = 1)

- 現在地ノードのラベル
- ホバー中のノードのラベル(その隣接ノードは通常どおり深さのルールに従う)

### 4. ラベル間引き(updateLabelVisibility)との関係

- **重要**: depthFade が十分小さい(例: 0.05 未満)ラベルは、間引きの候補から外す。
  見えないラベルが VISIBLE_LABELS の枠と重なり判定の場所を使うと、
  手前に出せたはずのラベルが減ってしまうため
- 候補に入ったラベルが新たに表示されるときは、不透明度0からフェードインさせる
- 02 で入れた「追加直後のラベル優先表示」にもこのルールを適用する
  (奥にあるものは、優先表示の期間中でも見えない)

### 5. 設定

- `labelDepthFade`(on/off)・`fadeStart`・`fadeEnd` を VizConfig に入れ、URL と leva(visual フォルダ)で変えられるようにする
- `current` は off(従来の見た目を保つ)、`rev2` と `mesh` は on

## 完了条件

- グラフを回すと、奥から手前に来たラベルが滑らかに現れ、手前から奥へ行ったラベルが消える
- 閾値付近でラベルがチラつかない
- 手前側に出ているラベルの数が、機能を入れる前より減っていない(同じ URL・同じ seed で比較)
- 現在地とホバー中のラベルは、どの角度でも読める
- ノード数 300 程度でもフレームレートが落ちない
- `npm test` が通る
- SPEC 6.3(ラベルの間引き)に深さのルールを追記し、12.2 を更新する

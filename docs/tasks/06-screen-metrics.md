# タスク06: 画面上の見え方を測る道具(rev2 と rev3 を同じ条件で数字で比べる)

CLAUDE.md と SPEC.md(1章・4章・6.3・6.9・8章・12章)を読んでから着手すること。
前提: 05(関連の強さを配置と動きで見せる)が完了していること

## 背景と目的

05 では、関連スコアと中心からの距離の相関(−0.33 → −0.75)や、上位・下位10件の平均距離(114 / 157)を
3D 座標で測った。しかし利用者が見ているのは画面である。ノードとラベルの大きさは画面上のピクセルで固定している
(`sizeAttenuation:false`)ので、奥行き方向のずれは見た目からほとんど読み取れない。3D で中心に近くても、
画面上では遠くに見えることがある。3D 座標の数字だけでは、見せ方の調整で体験が良くなったのかを判断できない。

そこで、表示や配置を変える改善(07 以降)の前に、**画面上でどう見えるか**を同じ条件で繰り返し測れる道具を作る。
12章で「比較の土台」を先に作ったのと同じ考え方で、今回はその土台に「測る物差し」を足す。

このツールでの「面白さ」の定義(2026-09-26 利用者と合意):
面白さの本質は wiki 自体にあり、このツールはそれを 3D の形で届ける。したがって
**判断しやすい・操作しやすい・視認性が高い・ちゃんと動く、はすべて「面白さを詰める」ことと同じ**である。
測る項目はこの4つに対応させる。

利用者との合意事項(2026-09-26):

- 測る道具を 06、次の見せ方の改善を 07 とする。06 では表示・配置・順位を**一切変えない**
- 比べるのは `rev2` と `rev3`。順位付けの重みが同じなので、同じ展開結果(`expansions`)のまま、配置と見た目だけを比べられる。
  `current` は顔ぶれが変わるので、今回は比べない
- 画面の大きさは **PC とスマホ横画面の両方**で測る
- 経路は3本(2章)
- 良し悪しの最終判断は、目で並べて見ることと身内の試用で行う。数字は「悪くなっていないか」「どこが効いていないか」を見るために使う
- フレームレートは環境で変わるので、道具では出さない。手で測った参考値を報告に添える
- 実機でのタッチ操作(ドロワー・タップの押し心地など)は、この道具の対象外。最後に実機で確かめる

## 用語

- **中心**: 経路の最後の記事(測る時点の現在地)
- **子**: 中心の `expansions` に記憶された記事のうち、画面に出ているもの。1つ前の中心は含めない
- **視点**: 測るときのカメラの位置と向き(4章)
- **仮想画面**: 測るときに使う、決まった大きさの描画領域(4章)。実際のウィンドウの大きさは使わない

## 仕様

実装に入る前に次を調べて報告し、利用者の返答を待つこと。

1. 3章の3「表示と同じ計算を使う」を満たすための切り出し方。
   力学の1ステップ・ラベルの選び方・画面への投影が、いま Graph3D.jsx のどこにあり、どう切り出すか。切り出しの規模

### 1. 入口

- `?debug=1` のときだけ `window.__viz.measure(options)` を使えるようにする。通常表示では定義しない
- 戻り値は Promise で、結果のオブジェクト(6章)を返す。同時に要約を `console.table` で出し、`window.__viz.lastMeasure` に結果を残す
- `options`(すべて省略可。省略時は全部を測る)
  - `routes`: 測る経路の key の配列(2章)
  - `presets`: 比べるプリセットの配列(既定 `['rev2', 'rev3']`)
  - `viewports`: 仮想画面の key の配列(既定 `['pc', 'phone']`)
- 測っている間は、ステータス行に進み具合(何本目の経路か)を出す

### 2. 経路の一覧

`src/debug/benchRoutes.js` に、測る経路をデータとして持たせる(`seed` は 1)。

| key | 開始記事 | 経路 | 性質 |
|---|---|---|---|
| `work` | 初音ミク | 鏡音リン・レン | 作品内。子の相互リンクが飽和し、共通ワードが多い(05 で共通15件) |
| `science` | 流体力学 | マグネシウム, ウラン | 分野をまたぐ。中心同士の手がかりが少ない(05 で共通8件・なし) |
| `voice` | 綾波レイ | 林原めぐみ | 作品の外の強い関係(01 で声優が確定枠に入った組) |

経路は後から足せるようにしておく(一覧に行を足すだけで測れる)。

### 3. 測り方の決まり(同じ入力なら同じ数字が出ること)

画面上の値は、そのままだとカメラの角度・ウィンドウの大きさ・時間(ラベルの切り替えの補間・ドリフト)でぶれる。
次の決まりで測り、**同じ経路・同じ設定なら、何度測っても完全に同じ数字になる**ようにする。

1. **展開結果**: 経路を URL から復元するときと同じ関数で取る(新しく書かない)。
   `presets` のすべてについて、順位付けに効く値(`wMorelike`・`wMutual`・`wLead`・`neighborLimit`・`seed`)が
   同じであることを確かめ、違えばエラーにして止める(顔ぶれの違う結果を黙って比べないため)。
   展開は1回だけ行い、全プリセットで共有する。Wikipedia への問い合わせは既存の仕組み
   (`linkCache`・`fetchWithTimeout`)を通し、叩きすぎないこと
2. **配置**: `buildGraph` でグラフを作り、(`seed`, 記事名)由来の初期位置から、表示と**同じ力学の計算**で
   alpha が `ALPHA_MIN` を下回るまで進める(上限 `MEASURE_MAX_STEPS` ステップ)。
   URL からの復元と同じく「一度に組んで落ち着かせる」形になる。
   実際の散歩ではクリックのたびに前の配置を引き継ぐので、そこは違う。この違いは報告に書く
3. **表示と同じ計算を使う**: 力学の1ステップ・ラベルの選び方(SPEC 6.3)・画面への投影は、表示のコードを写して作り直さない。
   **表示と測定が同じ関数を呼ぶ**ようにする。いま Graph3D.jsx の中にあるなら、純粋関数として `src/utils/` に切り出す。
   切り出しで表示の配置が変わってはならない(完了条件で照合する)。切り出しが大きくなりそうなら、0 の報告で相談する
4. **時間で変わるものは使わない**: パララックスドリフト・追加表示の震え・ラベルの出入りのフェードは加えない。
   位置はレイアウト座標を使う。ラベルは「その瞬間に、まっさらな状態で選び直したら」の結果を使う
   (前回表示していたラベルの優遇 `LABEL_KEEP_BIAS` を使わない)。深さフェードは補間後ではなく目標値で判定する。
   ただし M8(点滅。5章)だけは、表示と同じ優遇と間隔を使う(それ自体を測るため)
5. **表示中の画面を崩さない**: 測定は、画面に出ているグラフとは別に計算することが望ましい。
   表示中のグラフを使うしかない場合は、測り終えたら経路・設定・URL・カメラを測る前の状態に戻す
6. 追加表示(+ MORE)の分は測らない(URL に保存されない状態なので、再現できない)

### 4. 仮想画面と視点

**仮想画面**(値は 0 の報告で確かめ、constants.js に置く)

| key | 想定 | 描画領域の目安 |
|---|---|---|
| `pc` | 1280×800・サイドバー開 | 幅 1280 − 340、高さ 800 − 64(トップバー) |
| `phone` | 844×390 の横画面(`short-landscape`)・ドロワー閉 | 幅 844、高さ 390 − 44(トップバー) |

- カメラの画角と注視点までの距離は、**アプリがその大きさで開いたときと同じ決まり**で求める
  (SPEC 4章「高さが変わったら縮尺を保つ」の考え方を含めて。0 の報告で決まり方を確かめる)
- 大きさは CSS ピクセルで扱う(スマホの描画解像度の制限 `MOBILE_MAX_PIXEL_RATIO` は見た目の細かさだけに効くので、関係しない)

**視点**(注視点はどれも中心)

- `initial`: アプリが最初に置く向き。回さずに見る人が多いので、別に出す
- 周回視点: 中心を囲む球面上に均等に並べた `MEASURE_VIEWS`(8)方向。並べ方は決定論的にする(例: フィボナッチ球面)。
  カメラの上方向は (0,1,0) とし、視線がそれとほぼ平行になるときだけ (0,0,1) を使う
- 項目ごとに、周回視点の**平均と最悪値**を出す

### 5. 測る項目

頭の M 番号で報告・会話する。

**判断しやすい**

- M1 上位と下位の画面距離: 子を `relScore` の高い順に並べ、上位10件と下位10件それぞれについて、
  画面上の中心からの距離(px)の中央値と、その比(上位 / 下位)を出す。
  参考に、同じ組の 3D 距離の中央値も出す(3D と画面の差を見るため)。
  画面の外に出た子は中央値の計算から除き、その件数を別に出す
- M2 相関: `relScore` と画面距離の相関係数。3D 距離との相関も並べて出す
  (05 の −0.75 と比べられるよう、05 と同じ計算方法を使う。方法が分からなければピアソンにして、そう報告する)
- M3 上位の読める件数: 上位10件のうち、ラベルが読める状態(選ばれていて、深さフェードの目標が `LABEL_FADE_SHOW` 以上。
  うっすら表示の faint は含めない)の件数。読めない理由(overlap / depth / offscreen / rank / faint)ごとの件数も出す

**視認性**

- M4 ラベルの内訳: 画面の全ノードについて、表示しなかった理由ごとの件数(`window.__viz.labels()` の reason と同じ分け方)
- M5 中心付近の混み具合: 画面上で中心から `MEASURE_CROWD_RADIUS_PX` 以内にある一次ノードの数

**操作しやすい**

- M6 押し間違いの起きやすさ: 画面内のノードのうち、画面上の間隔が `2 × HIT_RADIUS_PX` 未満の組の数。
  `phone` では、指で押す前提の `MEASURE_TOUCH_PAIR_PX` 未満の組の数も出す(指はマウスより大きく、押す位置もずれるため)。
  中心を含む組は別に数える(中心のタップは追加表示なので、隣の球と取り違えると困る)

**ちゃんと動く**

- M7 落ち着くまで: 3章の2で、alpha が `ALPHA_MIN` を下回るまでのステップ数。上限に達したときは、そのことも出す
- M8 回転中の点滅: 落ち着いた配置で、`initial` から縦軸回りにカメラを 360° 回す
  (1ステップ `MEASURE_ROTATE_STEP_DEG`、60 ステップ/秒として時間を進める)。配置は動かさない。
  ラベルの選び直しは表示と同じ間隔(200ms 相当)・同じ優遇で行い、「消えてから1秒以内に再表示」の回数を数える
  (タスク03 の確認と同じ数え方)

### 6. 出力

- 結果のオブジェクト: 経路 × 仮想画面 × プリセット ごとに、M1〜M8 の値(視点ごとの値・平均・最悪値)と測った条件を持つ。
  条件は、経路・設定の全値・仮想画面の大きさ・カメラの距離と画角・視点の数・日時・進めたステップ数
- `console.table` の要約: 1行 = 経路 × 仮想画面 × プリセット。列は主な値(M1 の比・M2 の画面相関・M3・M5・M6・M7・M8)。
  rev2 と rev3 が上下に並ぶ順にする
- `window.__viz.measureMarkdown()`: 直前の結果を、レポートに貼れる Markdown の表にした文字列を返す
- 測定に数十秒かかってもよい。止まったように見えないよう、進み具合を出す(1章)

### 7. 定数(constants.js)

VizConfig には入れない(表示の調整値ではなく測る条件なので。`LEAD_EXTRA_MAX` と同じ扱い)。
決めた値と理由をコメントに残す。

| 定数 | 目安 | 意味 |
|---|---|---|
| `MEASURE_VIEWS` | 8 | 周回視点の数 |
| `MEASURE_MAX_STEPS` | 3000 | 落ち着くまで進める上限 |
| `MEASURE_CROWD_RADIUS_PX` | 60 | 混み具合を数える半径(背景グリッドの一番内側の円と同じ) |
| `MEASURE_TOUCH_PAIR_PX` | 44 | 指で押す前提の間隔(一般的なタッチ操作の目安) |
| `MEASURE_ROTATE_STEP_DEG` | 2 | 点滅を測るときに1ステップで回す角度 |
| `MEASURE_VIEWPORTS` | 4章 | 仮想画面の大きさ |

## テスト(tests/)

- 投影: 決まったカメラと点から、決まった画面座標になる。カメラの後ろにある点と、画面の外に出る点の扱い
- 周回視点: 数が `MEASURE_VIEWS` どおりで、各方向が単位長さで、毎回同じ並びになる。上方向の切り替え
- ラベルの選び方(切り出した関数): まっさらな状態で選ぶと、前回の表示に左右されない。前回の表示を渡すと、切り出す前と同じ結果になる
- 各項目の計算(中央値・相関・混み具合・近すぎる組・点滅の数え方)を、小さな入力で確かめる
- 力学を切り出した場合: 決まった入力で、切り出す前と同じ位置になる
- 順位付けに効く値が違うプリセットを渡すとエラーになる
- 既存のテストがすべて通る

- 3章の決まり: 展開は1回だけ(URL 復元と同じ `expandRoute`)、配置は初期位置から落ち着くまで、
  力学・ラベルの選び方・投影は表示と同じ関数、ドリフト・震え・ラベルの出入りのフェードは使わない、
  ラベルは「まっさらな状態で選び直したら」(M8 だけ表示と同じ優遇と間隔)
- 決定論: 同じページで2回続けて測り、日時以外のすべての値が一致することを確かめた。閲覧数の欠けは全組 0 件。
  利用者の手元の Chrome でも約2時間後(2026-09-26T14:08 UTC)に測り、日時以外のすべての値が下の表と一致した

表の読み方: 「a / b / c」は 初期視点 / 周回の平均 / 周回の最悪値。

## 事実として言えること

- **M1 比は、3経路とも rev3 の方が小さい。** 初期視点で work 0.51 → 0.46、science 1.12 → 0.86、voice 0.91 → 0.74。
  周回の平均でも同じ向き(0.62 → 0.54、0.97 → 0.82、0.93 → 0.77)
- **画面の比と 3D の比は一致しない。** work は画面の方が差が大きく見え(画面 0.51 / 3D 0.66)、
  science・rev2 は逆転する(3D では上位が近い 0.89 のに、初期視点の画面では上位の方が遠い 1.12)
- **周回の最悪値では、rev3 でも上位と下位の差がほぼ消える向きがある。** science 1.01、voice 0.97
- **M2 の画面相関は、3経路とも rev3 の方が強い**(work −0.55 → −0.65、science −0.09 → −0.26、voice −0.11 → −0.39)。
  ただし 3D の相関(−0.73、−0.41、−0.56)より弱い。05 の −0.75(3D)に近いのは work・rev3 の 3D 相関 −0.73
  (05 の計算方法は記録が無いので、ここではピアソンで出した)
- **M3: 上位10件のうち読めるラベルは、pc で 1〜3 件、phone の初期視点では全組 0 件。**
  読めない理由の最多は depth(10件中 4〜5件。深さフェードの目標が `LABEL_FADE_SHOW` 未満)。
  work・science では rev3 の方が読める件数が少ない(2 → 1、3 → 1)。voice は同じ(3)
- **phone は pc と同じカメラ距離で、画面上の距離が 346/736 ≈ 0.47 倍になる**(M1 の px がちょうどその比)。
  そのため比と相関は pc と phone で同じ値で、違いはラベルの重なり(M4 overlap: pc 11〜38 → phone 21〜48)と
  混み具合(M5: pc 7〜12 → phone 36〜41。一次ノードのほぼ全部が中心から 60px 以内)、近すぎる組(M6)に出る
- **M6: phone では画面内の 67〜79 ノードに対し、32px 未満の組が 348〜496、指の目安 44px 未満が 633〜888。**
  中心を含む組も 44px 未満で 27〜36 ある。pc は 32px 未満が 61〜95 組、中心を含む組は 2〜4
- **M7 はすべて 418 ステップ**(alphaDecay 0.99 で alpha が 0.015 を下回る回数そのもので、配置によらない)
- **M8(360° を 3 秒で回す。ラベルの選び直し 15 回)で、「消えて1秒以内に再表示」は pc 26〜35 回、phone 12〜29 回。**
  rev2 と rev3 の差は経路によって向きが違う(work pc 35 → 26、work phone 12 → 16)
- カメラ距離(910〜999)は、54 ステップ目と落ち着いた後でほぼ変わらない
  (work・rev2 910.6 / 910.9、science・rev3 924.8 / 948.9)。外接箱には1つ前の中心の子も入るので、今の中心の周りだけを見るには引きすぎた距離になっている

## 解釈・推測(数字から言い切れないもの)

- rev3 の「関連が強いほど近く」は 3D だけでなく画面上でも効いている。ただし向きによっては投影で打ち消されるので、
  回さずに見る人(初期視点)と回して見る人とで効き方が違うはず
- 上位の子のラベルが depth で消えやすいのは、上位の子ほど中心の近く(3D の中央値で 106〜163)にいて、
  その約半分が中心より奥に回るためだと思われる。深さフェード(rev2 以降。奥 60 で消える)と
  「関連が強いほど近く」(rev3)が、上位のラベルについては打ち消し合っている可能性がある。07 の候補
- phone で読めるラベルが 0 件なのは、グラフ全体が小さく見えて(上位の子が中心から 26〜47px)ラベルが重なり合うのが主因と思われる。
  カメラ距離の決め方(全体を収める)を画面の大きさや「今の中心の周り」に合わせて変えると、M3〜M6 が大きく動くはず
- M8 の回数が多いのは、2°/ステップ(120°/秒)が手で回すより速く、選び直し1回あたり約 26° 回るためだと思われる。
  タスク03 の「39 回 → 1 回」(手でドラッグ)とは回し方が違うので直接は比べられない。07 以降の前後比較(相対値)に使う

## フレームレートの参考値

## 測り方の限界

- **一度に組んだ配置である。** URL からの復元と同じく、全部の記事を展開してから初期位置から落ち着かせている。
  実際の散歩はクリックのたびに前の配置を引き継ぐので、同じ経路でも配置は違う
- **追加表示(+ MORE)の後は測っていない**(URL に保存されない状態なので再現できない)
- **タッチ操作は測っていない。** M6 は画面上の間隔だけで、指の押し心地・ドロワー・タップの反応は実機で確かめる
- 閲覧数は日によって変わるので、日をまたぐと球の大きさ(= ラベルの置き場所・当たり判定)が変わり、数字が少し動くことがある
- 仮想画面は端末の公称値で、実機のアドレスバーで 100dvh が低くなる分は入っていない
- ラベルの深さフェード・点滅は目標値と選ばれたかで判定しており、補間中の見た目(うっすら出ている途中)は数えていない

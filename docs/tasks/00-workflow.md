# docs/tasks — rev2 改善タスクの進め方

このフォルダには rev2 に向けた改善タスクの指示書を置いている。
Claude Code はこのファイルのルールに従って、01 から順に1つずつ実装すること。

## 着手の前提

別途依頼済みの次の2件が完了し、利用者の確認が済んでいること。

- 力学パラメータの VizConfig 化(デバッグパネルで調整できるようにする)
- スマホ横画面の対応とサイドバーの格納機能

未完了・確認待ちのものがあれば、このフォルダのタスクには着手せず、その旨を報告して止まる。

## タスク一覧と状態

状態は利用者が「OK、次へ」と言った時点で Claude Code が更新する。

| No | ファイル | 内容 | 前提 | 状態 |
|---|---|---|---|---|
| 01 | `01-relevance-score.md` | 関連スコア方式(相互リンク・冒頭リンクの加点) | VizConfig 化 | 完了 |
| 02 | `02-more-links.md` | 関連リンクの追加表示(中心タップ / + MORE) | 01 | 完了 |
| 03 | `03-label-depth-fade.md` | 奥のラベルを深さに応じて透けさせる | VizConfig 化・02 | 未着手 |

状態の値: `未着手` → `実装済み・確認待ち` → `完了`

## 進め方のルール

### 最初に1回だけ

1. 01〜03 をすべて読み、全体像を把握する
2. 実装に入る前に、次の点を報告して止まる
   - 指示書同士の矛盾・依存関係の問題
   - 指示書と現在のコードとのずれ(指示書が前提にしている構造が実際と違う、など。
     特に、実装済みの VizConfig 化・横画面対応の結果と食い違う箇所)
   - 実装順を変えた方がよい理由があればその提案
3. 利用者の返答を待ってから 01 に着手する

### 各タスクで

1. 着手前に、そのタスクの指示書と CLAUDE.md・SPEC.md の関係箇所を読み直す
2. 実装する。指示書どおりにできない・指示書より良い方法がある場合は、
   **勝手に変えずに**、その時点で止まって理由を添えて相談する
3. 完了条件を自分で確認できる範囲で確認する(`npm test`・`npm run build`・Console のエラーなど)
4. タスク単位でコミットする(1タスク = 1コミット以上。複数タスクを1コミットに混ぜない)
5. SPEC.md・README.md・CLAUDE.md の更新も、そのタスクのコミットに含める
6. 下の「報告の形式」で報告し、**そこで必ず止まる**

### 止まる・待つ

- 利用者が「OK、次へ」と言うまで、次のタスクに進まない
- 利用者が修正を頼んだら、同じタスクの中で直して、もう一度報告して止まる
- **main への push は、利用者が「push して」と言うまで行わない。**
  push すると GitHub Actions で公開サイトに自動反映されるため、
  利用者がローカルで見た目と操作を確認してから公開する
- 「OK、次へ」と言われたら、上の表の状態を更新してコミットしてから次のタスクに進む

## 報告の形式

```
## タスク NN 完了報告

### 変更点
- (何をどう変えたか。ファイル名と要点)

### 指示書から変えた点・判断した点
- (なければ「なし」)

### 自分で確認したこと
- npm test: 結果
- npm run build: 結果
- その他

### 利用者が確認すべき手順
1. (npm run dev で開く URL、試す操作、期待する見え方を具体的に)

### 気になっている点・次のタスクへの影響
- (なければ「なし」)

### コミット
- (コミットの一覧。push はまだしていないこと)
```

確認手順はターミナル操作に不慣れでも実行できるよう、コマンドは丸ごとコピーできる形で書くこと。
